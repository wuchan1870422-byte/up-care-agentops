## 30 秒介绍

这是一个独立、非官方的诊所服务运营概念应用，把咨询补问、资料检索、沟通质检、预约意向、工单、人工审核和运营统计连起来。重点是业务闭环可操作、数据可保存、过程可追踪。当前用规则实现自动化，没有调用大模型，不提供临床判断，也不代表优复内部系统。

可以如实说明：“我在 AI 编程辅助下开发和迭代这个项目，能解释它的调用链、测试和现有边界。”不要声称所有代码都是独立手写，或已交付医疗生产系统。

## 真正实现了什么

| 分类 | 实际行为 |
|---|---|
| 可运行业务 | 保存咨询、联系人、线索、意向、工单、审批、任务；角色检查、状态流转、事务、幂等、版本、报告和 CSV 下载 |
| 规则模拟智能 | 正则提取意图和字段，固定步骤生成回复，风险词规则检查，保守 SOAP 草稿；不能理解任意患者表达 |
| 真实检索 | 资料分块，英文词和中文双字分词，按关键词匹配和词频权重排序；返回来源和版本 |
| Mock / 虚构数据 | 演示患者、种子规范、Mock CRM 同步、Mock 预约查询；没有实际排班、报销核验或外部系统写入 |
| 没有接通 | LLM、Embedding、向量数据库、模型自主 Tool Calling、生产身份认证、共享 PostgreSQL；Coze 只有未验证的可配置适配器 |

不能把关键词检索称为已完成“大模型 RAG”；准确表达是“检索加规则回复”。有业务工具函数，但调用者是 TypeScript 控制器，不是模型。Prompt Lab 对模板和固定风险规则做回归，不调用模型，也不把模板自动用于主咨询。

## 真实技术栈与调用链

当前锁文件安装：Next.js 16.4、React 19.3、TypeScript、Zod 4.6、Lucide；Node 24 的 SQLite、sql.js 1.14、IndexedDB；本地 PDF 提取使用 pdf-parse 2.4。界面采用自建 CSS。测试是 Vitest 和 Playwright，发布是 GitHub 与 Vercel。没有使用 Prisma、Tailwind、React Flow 或 OpenAI SDK。

**本地 `/`：** 点击按钮 → React 工作台 → `transport.ts` 发 HTTP 请求 → Next Route Handler 检查会话、来源和参数 → `operations.ts` / `workflow.ts` 执行业务 → 检索与工具 → Repository → 本地 SQLite 文件 → 返回 JSON 或 SSE 事件 → 页面显示结果。

**公开网站和 `/demo`：** 点击按钮 → `transport.ts` → `browser-store.ts` → 同一套业务函数 → 浏览器中的 SQLite WASM → 将数据库快照存入 IndexedDB → 页面显示结果。节点进度是浏览器回调，不是公网 SSE。Vercel 不保存这些业务数据；公开业务 API 返回 503，健康接口仍可返回 200。

SSE 就是服务器持续发送事件，让页面逐步更新。IndexedDB 是浏览器里的持久数据库：刷新通常保留数据，清除站点数据会删除，不会跨设备共享。健康检查成功也不能证明全部业务、模型或数据库连接正常。

## 5 分钟现场演示

准备使用普通浏览器，允许站点存储。不要输入真实患者身份、病历或保险号码。不需要 API Key，不产生模型调用费用。

1. 打开公开 Demo，首页点击 **开始面试演示**。应用创建独立虚构空间，保留旧空间数据；上方显示步骤说明。强调当前是规则模式。
2. 输入框已填入 `虚构演示：我想预约`。点击 **运行 Agent**，展示缺少院区和时间的补问；此时不创建工单。
3. 点击 **填入补充信息**，内容为 `虚构演示：前滩周六上午，希望英语沟通，保险权益需要核实。`，再运行。展示十个实际节点、引用来源与版本、预约意向及待审核工单。说明这是意向，不是确认预约；保险仍需人工核实。
4. 保持客服角色，打开 **服务工单**，点击 **导出 CSV**，展示“无权”错误与仍存在的工单。然后切换 **医疗审核员**，打开该工单并 **通过审核**；切换 **门诊运营**，依次 **开始处理**、**完成工单**。
5. 返回 **运营总览**，展示 1 条已完成工单；刷新后核对持久化。说明公开版只保存在当前浏览器。

这条流程在两种存储模式都有自动化测试。不要在现场演示中把前滩等种子摘要当作实时排班信息。出现错误时先阅读红色提示；存储被浏览器禁止时换普通窗口并允许存储；新建演示空间是切换空间，旧空间没有自动找回入口。不能承诺清除站点数据后还能恢复。

## 本轮三个缺陷与当前局限

修复：正文编辑曾重置文档限阅/停用状态；低权限角色曾可用旧幂等键重放限阅咨询；重复或过期审批曾能覆盖工单后续状态。新增回归先在原代码失败，再通过修复；详见审计。

现有边界：角色下拉框只是演示，不是可信身份认证。关键词和正则会漏判或误判，不能验证临床安全。流程是同步有限状态流程，不是可自由规划的 Agent 或后台任务系统。浏览器快照可能随清理丢失，无 Web Locks 时跨标签页并发保证较弱。工作流时间预算在节点边界检查，不能中断正在执行的长任务。没有完成专业 WCAG 审查、临床有效性评估或生产负载测试。

## 将来如何真正集成（设计方案，当前未实现）

先建立正式账号认证、服务端权限和共享数据库，再连接模型；API 密钥只能放服务端，不能放浏览器。是否使用付费服务须另行授权。

- **LLM：** 给模型明确的非诊疗任务，让输出符合结构化 Schema；设置超时、调用预算和失败提示。规则仍用于权限及高风险拦截，不能只相信模型自检。
- **RAG：** 先按用户权限过滤资料，再分块、生成 Embedding 并保存版本，在向量/关键词混合检索后把片段给模型；要求引用，不足时明确无法回答。用独立人工标注案例测引用正确率与拒答，而不是只看演示能跑。
- **Tool Calling / Agent：** 模型提出工具名和参数，服务器校验白名单、Schema、角色及幂等键，再执行；高风险写入等待人工批准。保留实际请求、工具结果、耗时与错误轨迹；用持久任务机制处理重试，不让模型任意执行 SQL 或外部动作。

## 面试官可能问的 15 个问题

1. **项目解决什么问题？** 把分散的咨询、资料、工单和审核串联起来，减少重复录入并保留过程证据。没有真实业务上线数据，不能承诺提升百分之多少。
2. **这是真 AI 吗？** 当前不是大模型应用。规则提取和模板回复实际运行；“Agent”名称表示工作流演示，不能证明模型推理能力。
3. **为什么用 Next.js？** 一套 TypeScript 工程同时管理 React 页面和本地 API，部署方便。公开版的浏览器执行是为了让现有 SQLite 项目无需共享后端也能演示，不是生产架构的最终选择。
4. **前端与后端怎么通信？** 本地通过 JSON API 和 SSE；公开版通过浏览器适配器调用相同业务函数，没有把每次咨询发给服务器。
5. **数据都是 Mock 吗？** 操作产生的工单、版本、统计和存储是真的；患者和种子规范是虚构的，外部 CRM 与排班是 Mock。真实持久化不等于真实外部业务完成。
6. **RAG 做到了什么？** 做到了分块、权限过滤、关键词检索和引用。没有 Embedding、向量检索或 LLM 增强生成，因此不宣称完整 LLM RAG。
7. **关键词怎么排序？** 英文按词、中文按相邻双字切分。命中稀有词的权重较高，取前五片段。算法不了解语义，同义词可能检索不到，也不是标准完整 BM25 实现。
8. **有没有 Tool Calling？** 有受控工具函数，参数由 Zod 检查，权限由业务层检查。但当前是代码选择工具，不是模型输出 function call。
9. **工作流为什么是十个节点？** 将提取、补问、检索、草稿、质检、业务写入及记录拆开，方便定位失败。缺少字段会提前停止，并非每次都有十个节点；不支持任意拖拽流程。
10. **什么是幂等？** 同一个操作重发不应重复创建工单。系统保存操作键与结果，失败重试沿用原始运行键；同键不同参数会冲突，读缓存结果也必须重新检查权限。
11. **为什么要事务？** 一组相关数据库写入应一起成功或一起撤销，避免只有审批状态更新、目标工单没更新。事务不保证外部 CRM 同时成功；真正外部集成还需要独立恢复设计。
12. **角色控制等于登录安全吗？** 不等于。身份认证证明“你是谁”，授权检查“你能做什么”。本项目角色可切换，只能展示授权逻辑，不能用于生产敏感数据。
13. **怎么避免不当医疗建议？** 当前使用明确的非临床范围、固定回复、高风险规则与人工审核；SOAP 不编造客观检查、评估和方案。这些措施不构成临床安全验证，规则仍会误判。
14. **测试通过能证明什么？** 证明已覆盖的业务、回归和浏览器流程符合预期。77 条评测是固定虚构规则案例，不是模型或临床准确率。原有测试曾全通过仍漏掉本轮三个问题，所以需要针对真实失败补回归。
15. **下一步最值得做什么？** 正式认证与共享服务端存储优先，其次引入可控模型和权限先行的检索，补独立效果评测与负载测试。避免先堆模型功能，却缺少可信权限、数据恢复和失败处理。
