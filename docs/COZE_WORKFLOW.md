# Coze 适配与复现说明

状态：后端封装存在，尚未连接验证。不会因环境变量存在就把 connected 显示为 true。

服务端 `COZE_API_TOKEN` 与 `COZE_WORKFLOW_ID` 配置后，管理员可通过本地 POST `/api/coze` 触发适配器。调用 `https://api.coze.cn/v1/workflow/run`，20 秒超时，验证 HTTP 和业务 code，并写入成功/失败审计；原始 Token 不进入日志或客户端。

## 在 Coze 平台复现 Workflow A

1. 输入节点：`input` 为虚构患者文本；禁止真实身份信息。
2. LLM 结构化节点：输出院区、时间、语言需求、保险问题、缺失字段和转人工标志；不存在的信息保留空值。
3. 知识检索节点：导入公开背景摘要与明确标记的演示服务规范，返回出处和片段。
4. 回复草稿节点：只使用检索证据，不诊断、不承诺疗效/保险/排班。
5. 规则校验节点：校验 JSON Schema 和风险；高风险或证据不足必须转人工。
6. 输出：`draft`、`citations`、`requires_human_review=true`；不连接短信、邮件或真实预约接口。

模型、账户套餐、工作流发布状态以及接口契约均须在实际 Coze 项目中验证。本文是可复现设计，不是已创建的线上 Coze 工作流。不能把当前封装描述为已接入企业系统。
