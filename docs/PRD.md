# Product Requirement Document

原始完整需求为 [MASTER_SPEC.md](MASTER_SPEC.md)，其目标和规模未删除。本文件只说明已交付版本的产品边界与验收方式。

## 目标

用一次可重复操作展示：咨询 → 信息提取 → 可核实知识 → 服务回复草稿 → 风险审查 → 预约意向及工单 → 人工审批 → 运营分析。服务于 AI 应用开发岗位作品展示，不提供真实医疗服务。

## 用户与权限

| 角色 | 核心工作 |
|---|---|
| 客服 | 提交虚构咨询、质检、登记意向、查看工单 |
| 门诊运营 | 咨询、工单分配和处理、随访任务 |
| 医疗审核员 | 审核医疗相关事项、文书草稿和知识规范 |
| 运营管理者 | 审核一般服务工单、运营统计、评测、CSV |
| 系统管理员 | 管理所有演示业务数据、知识与配置入口 |

本地角色存入服务端会话，所有写入检查权限；角色切换本身公开用于演示，因此不构成生产认证。公开浏览器版所有数据归当前浏览器，权限只是演示约束。

## 验收标准

1. 新空间初始业务指标为零，知识文档有公开来源或虚构标签。
2. Scenario A 必须记录院区、时间、英语需求、保险问题；不能确认真实预约。
3. Scenario B 必须检出未经依据的判断、疗效承诺和保险承诺。
4. Scenario C 的院区查询展示可点击公开出处。
5. Scenario D 保存原始随访摘录及待核实事项，创建工单和人工任务。
6. Scenario E 文档编辑后版本递增，新内容立即可被检索。
7. Scenario F 实际执行 20 条质检，保存逐条风险记录和统计。
8. 刷新后记录仍存在；失败有提示；重复请求不能重复写入工单。
