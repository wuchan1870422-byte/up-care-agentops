## 架构结论

Next App Router + React 单工作台，业务集中于 Operations / Workflow / Repository。本地使用 Node SQLite、会话 Cookie、API 和 SSE；Vercel 公开版使用 sql.js + IndexedDB，在浏览器执行相同业务，节点以回调更新。公开角色可以自行切换，没有正式认证或跨设备共享数据库。

咨询、工单、任务、审批、知识版本、记录统计及报告是真实操作与持久化。患者与种子业务规范是虚构数据；Mock CRM/预约只读写当前空间，没有外部医疗系统连接。意图、补问、质检和回复使用正则与模板；检索使用关键词权重，不是向量检索。没有 LLM、Embedding 或模型自主 Tool Calling。Coze 适配器代码存在，但未配置/在线验证。完整职责与调用链见 [面试指南](INTERVIEW_GUIDE.md)。

## 三个优先修复的可复现问题

| 问题 | 复现与影响 | 实际修复 |
|---|---|---|
| P1 文档编辑改变访问范围 | 创建限阅、停用文档后仅修改正文；Schema 默认值将其改成全员可见且启用 | 更新时保留未提供的旧 metadata；表单明确编辑可见性/检索开关，保留版本记录 |
| P1 限阅咨询可被缓存重放 | 高权限咨询引用限阅资料，低权限使用同一操作键再次请求，原实现返回包含原文的 Run；也可向隐藏会话继续写入 | 返回旧 Run、重试、续写会话及相关工具读取前重新检查引用权限；切换角色清空页面缓存引用和编辑正文 |
| P1 过期审批覆盖后续状态 | 不同操作键对同一目标建立多条待审核；旧审核在工单已完成后仍可将它改为拒绝 | 对待审目标复用现有待审记录；审批要求目标仍待审核，否则 409 并回滚，禁止覆盖已完成状态 |

## 质量检查与尚存问题

API 使用 Zod、参数化 SQL、空间过滤、Origin 检查及统一错误响应；CSV 有公式转义。已有测试覆盖非法参数、角色权限、状态转换、事务回滚、预算失败和重试。UI 使用表单可访问名称、工单弹窗 Escape/焦点恢复、移动布局与主题；专业无障碍认证尚未进行。

本轮保留的后续事项：上传实际文件大小在解析 formData 后验证，缺少流式限量/速率限制；CSP 仍允许 inline script/style；日期筛选语义校验较弱；浏览器无 Web Locks 时并发保护较弱；主工作台较大，数据库 Schema 有重复；处理时长口径包含等待。不是生产安全或性能保证，不适合真实患者数据。限阅修复针对引用内容和相关运行访问，不表示已完成全系统生产 RBAC 审计。

依赖以锁文件为准；生产依赖漏洞检查结果及工程/browser 实测结果见 [TEST_REPORT](TEST_REPORT.md)。既有 CI 先检查代码再运行双存储 E2E；Vercel Git 部署独立触发，当前配置没有强制等待 GitHub CI，因此本轮先完成本地验证再推送。
