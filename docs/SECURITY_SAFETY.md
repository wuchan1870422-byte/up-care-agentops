# 安全与医疗边界

## 已实施

- 本地 HttpOnly/SameSite 会话；服务端角色校验；工作空间范围查询；写入 Origin/Host 校验。
- Zod 校验、参数化 SQL、事务、唯一幂等键、状态机、正文大小限制与演示空间记录上限。
- 执行器只调用白名单工具。Prompt Injection 检测触发转人工，不能覆盖业务权限或跳过审核；不执行用户提供的代码。
- 受限知识不进入低权限检索；包含受限引用的历史运行和对话在降权后隐藏。
- CSV 公式前缀转义；链接只接受 HTTP(S)；CSP、nosniff、frame-ancestors 和 Referrer-Policy。
- `.env.local`、Vercel/CLI 认证、数据库、测试资料、临时工具均被忽略；公开项目不包含密钥。
- 所有患者数据只允许使用虚构演示材料；UI 明示禁止真实身份及医疗信息。规则能检测部分身份信息，但不能保证自动识别所有真实信息。
- 医疗工单和文书要求医疗审核员/管理员处理；SOAP 不自动生成检查结果、诊断或治疗计划。

## 明确限制

本地角色切换是公开演示功能，不能代替生产认证；浏览器版用户可控制本机数据，不能视为安全多租户服务。规则质检不能识别全部风险，不是医疗监管合规认证。尚未进行外部渗透测试或临床验证。

不得自动发送患者通知，不读取企业内部资料，不接入真实排班，不将草稿写入正式医疗文书。生产上线前还需正式身份认证、PostgreSQL 行级隔离、限流、备份、数据保留与删除策略，以及专业人员审查。

依赖检查发现开发工具链中 `braces` 及其上游依赖通报了高危问题；生产依赖检查当前为 0 项。没有使用会把 Next ESLint 降级到不匹配大版本的 `npm audit fix --force`，详见测试报告。
